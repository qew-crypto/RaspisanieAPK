# Расписание — приложение и хост

МБОУ СШ №6 (г. Гуково). Приложение показывает [сайт расписания](https://raspisanie.nikasoft.ru/15312761.html). Пока оно закрыто, хост раз в 5 минут проверяет дату обновления и пишет в Telegram.

Токен бота в репозиторий не входит. Его нужно положить только в `host/.env` на сервере.

## Хост

На сервере, где уже крутится бот, не запускай второй монитор с тем же токеном: уведомления придут дважды. Либо оставь старого бота, либо останови его и запусти этот монитор.

```bash
cd host
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
cp .env.example .env
# впиши BOT_TOKEN в .env
./venv/bin/python monitor.py
```

Проверка каждые 5 минут. Подписка — `/start`, отписка — `/stop`, текущая дата — `/update`.

Если у старого бота уже есть подписчики, скопируй его `data/subscribers.json` в `host/data/` до запуска. Формат тот же: JSON-список chat id.

Служба: `host/raspisanie-monitor.service`. Поправь в ней пути и положи файл в systemd.

Разовая проверка без приёма команд, например из cron:

```bash
./venv/bin/python monitor.py --once
```

Cron не заменяет долго работающий процесс: команды `/start` и `/stop` принимает только он.

## Приложение

Исходники в `android/`. Открой эту папку в Android Studio и собери APK, либо скачай debug-сборку из GitHub Actions после пуша в `main`.

Приложение:

- открывает сам сайт расписания;
- в шапке показывает, когда сайт последний раз выгрузил расписание;
- если с прошлого запуска выгрузка сменилась, показывает уведомление.

Надёжные уведомления при закрытом приложении идут с хоста в Telegram. Android сам по себе раз в 5 минут в фоне это не гарантирует.
